# 데이터 엔지니어링 수명 주기 (Data Engineering Lifecycle)
> 원천 시스템에서 데이터가 생겨나 분석·ML 등에 쓰이기까지 거치는 단계들. 데이터 엔지니어링을 특정 도구가 아닌 단계로 바라보는 틀.

## 핵심
5단계: **생성 → 저장 → 수집 → 변환 → 서빙**

## 세부 / 동작 방식
| 단계 | 설명 (보충) | 예시 |
|---|---|---|
| 생성(Generation) | 원천 시스템이 데이터를 만든다. 데이터 엔지니어가 통제하지 못하는 경우가 많다 | 운영 DB, 앱 이벤트, IoT |
| 저장(Storage) | 다른 모든 단계의 바탕. 비용·접근 빈도·확장성 고려 | 오브젝트 스토리지, 데이터 웨어하우스 |
| 수집(Ingestion) | 원천에서 데이터를 가져온다. 배치 vs 스트리밍, 푸시 vs 풀 | [[Kafka]], CDC |
| 변환(Transformation) | 쓸모 있는 형태로 정제·결합·모델링 | SQL, Spark, dbt |
| 서빙(Serving) | 분석, ML, 역 ETL 등으로 가치를 전달 | BI 대시보드, 피처 스토어 |

- (보충) 저장이 수집보다 앞에 나열되는 이유: 저장은 한 단계라기보다 수명 주기 전체에 걸쳐 쓰이기 때문이다.

### 드러나지 않는 요소 (Undercurrents) (보충)
모든 단계에 걸쳐 고려해야 하는 것: 보안, 데이터 관리, DataOps, 데이터 아키텍처, 오케스트레이션, 소프트웨어 엔지니어링.
