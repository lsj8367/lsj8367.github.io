# 데이터 중심 애플리케이션 설계 1장 - 신뢰성·확장성·유지보수성

- 원본: [[raw/데이터 중심 애플리케이션 설계/1장. 신뢰할 수 있고 확장 가능하며 유지보수하기 쉬운 애플리케이션|1장 노트]]
- 종류: 책 장 (직접 정리한 노트)
- 책: [[데이터 중심 애플리케이션 설계 (Designing Data-Intensive Applications)]]

## 요약
애플리케이션은 계산 중심에서 데이터 중심으로 옮겨 가고 있으며, 병목은 CPU가 아니라 데이터의 양·복잡도·변화 속도다. 데이터베이스·캐시·큐 같은 도구들의 경계가 흐려지고 단일 도구로 요구사항을 충족할 수 없게 되면서, 이들을 조합한 것을 하나의 "데이터 시스템"으로 바라본다. 좋은 데이터 시스템이 갖춰야 할 세 가지 속성으로 신뢰성·확장성·유지보수성을 제시한다.

## 핵심 주장
- 데이터 중심 애플리케이션의 제약은 CPU가 아니라 데이터의 양·복잡도·변화 속도다. → [[데이터 중심 애플리케이션 설계 (Designing Data-Intensive Applications)]]
- Redis·Kafka처럼 분류 경계가 모호한 도구가 늘었고, 단일 도구로 저장과 처리 요구를 모두 만족시킬 수 없어 여러 도구를 묶어 "데이터 시스템"으로 본다. → [[데이터 중심 애플리케이션 설계 (Designing Data-Intensive Applications)]]
- 신뢰성: 하드웨어·소프트웨어 결함, 인적 오류에도 올바르게 동작해야 한다. 결함은 장애와 다르다. → [[신뢰성 (Reliability)]]
- 인적 오류 대응: 오류 가능성 최소화 설계, 실수 지점 분리, 철저한 테스트, 빠른 복구, 모니터링. → [[신뢰성 (Reliability)]]
- 확장성: scale-up / scale-out 구분, 비공유 아키텍처, 탄력적 시스템. → [[확장성 (Scalability)]]
- 유지보수성: 운용성·단순성·발전성. 발전성에는 테스트 코드 유지가 좋은 방법. → [[유지보수성 (Maintainability)]]
