# 데이터 중심 애플리케이션 설계 2장 - 데이터 모델과 질의 언어

- 책: [[데이터 중심 애플리케이션 설계 (Designing Data-Intensive Applications)]]

## 요약
관계형 모델은 구현 세부를 깔끔한 인터페이스 뒤에 숨기는 것을 목표로 했고, 1970~80년대 네트워크·계층 모델과의 경쟁에서 이겼다. 이후 확장성·오픈소스 선호·특수 질의·유연한 스키마 요구로 NoSQL이 등장했다. 객체지향 코드와 테이블 사이에는 변환 계층이 필요한데, 이를 임피던스 불일치라 한다.

## 핵심 주장
- 관계형 모델의 목표는 구현 세부를 인터페이스 뒤로 숨기는 것. → [[관계형 모델과 문서 모델 (Relational vs Document Model)]], [[유지보수성 (Maintainability)]] (추상화)
- 1970~80년대 네트워크 모델·계층 모델이 대안이었으나 관계형 모델이 우위. → [[관계형 모델과 문서 모델 (Relational vs Document Model)]]
- NoSQL이라는 이름은 특정 기술을 가리키지 않아 부적절하지만 굳어졌다. 채택 이유 4가지. → [[관계형 모델과 문서 모델 (Relational vs Document Model)]]
- 객체 관계형 불일치(임피던스 불일치). → [[관계형 모델과 문서 모델 (Relational vs Document Model)]]
